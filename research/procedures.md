## Phase 1A — Environment and reproducibility infrastructure

**Procedure 1. Establish a version-controlled project structure.**
Created a Git repository with a strict separation between immutable source data
(`data/raw/`), derived data (`data/processed/`), analysis code (`scripts/`), and
outputs (`reports/`). Configured `.gitignore` so that large data files and all
regenerable outputs are excluded from version control, while documentation, code,
and the provenance manifest are tracked.
*Rationale:* raw data is the only project component that cannot be regenerated by
running code; isolating it as read-only makes any downstream error recoverable.

**Procedure 2. Pin the software environment.**
Recorded all required Python libraries and versions in `requirements.txt`
(pandas 3.0.5, numpy 2.4.6, scipy 1.17.1, matplotlib 3.11.1, h5py 3.16.0;
Python 3.11.15). *Rationale:* prevents version drift, in which a result changes
because a dependency silently updated.

## Phase 1B — Dataset identification and acquisition

**Procedure 3. Resolve the dataset identifier to a citable record.**
Queried the Dryad public REST API (`/api/v2/datasets/{doi}`) to resolve the
identifier `n2z34tn5s` to **DOI 10.5061/dryad.n2z34tn5s**, confirming title,
11 authors, and deposit contents.

**Procedure 4. Obtain authorized programmatic access.**
The public file-download route was found to be protected by a JavaScript
proof-of-work anti-bot challenge, which returns an HTML page rather than data to
any script. Rather than circumventing this protection, the repository-supported
route was used: a Dryad API account (ORCID authentication) issuing OAuth 2.0
client credentials, exchanged at `https://datadryad.org/oauth/token`
(`grant_type=client_credentials`) for a bearer token used against the
authenticated download endpoint. Credentials were supplied only as environment
variables, never written to any file, and the API account was deleted after use.

**Procedure 5. Download the dataset programmatically with checksum verification.**
Ran `scripts/01_download_dataset.py`, which enumerates the deposit's files via the
API, streams each to `data/raw/`, and verifies the SHA-256 hash of every file
against the checksum published by Dryad.
*Result:* Dryad **version 6**; `MINDFUL_Data.zip` (411,951,588 bytes) and
`README.md` (3,348 bytes). Both checksums matched.

**Procedure 6. Record provenance.**
The download script wrote `data/raw/download_manifest.json`, recording DOI, Dryad
version number, filenames, byte counts, SHA-256 digests, source URLs, and the UTC
timestamp of download. This file is committed to version control.

## Phase 1C — Structural characterization (no analysis)

**Procedure 7. Inventory the archive without modifying it.**
Ran `scripts/02_inspect_dataset.py --extract`, which unpacked the archive into
`data/raw/extracted/` (leaving the original `.zip` intact), then enumerated all
files, types, sizes, and the directory hierarchy, and opened each `.mat` file to
report every variable's name, shape, and data type.
*Result:* 162 `.mat` files in 54 block folders; recorded in `reports/inventory.json`.

**Procedure 8. Read the dataset's official documentation.**
Read the authors' `README.md` from the deposit and compared every variable
description against the files themselves, rather than inferring meaning from
variable names.

**Procedure 9. Cross-reference the authors' published analysis code.**
Cloned the authors' MATLAB analysis repository (`github.com/ewinapun/MINDFUL`,
commit `1809e13`) and read their data-loading routine to establish the expected
file organization and processing conventions.
*Note:* this step produced one incorrect inference (see Procedure 10), which the
official documentation subsequently corrected.

**Procedure 10. Verify field locations against the files.**
Comparison of the authors' README against the code-derived expectation revealed
that `startStops`, `excludeTrials`, and `moveDirVect` reside in `task.mat`, not
`data.mat`. The authors' loader reads all three files into a single workspace, so
the code alone cannot reveal a variable's file of origin. The data loader was
corrected accordingly.

**Procedure 11. Determine the array indexing convention empirically.**
MATLAB indexes arrays from 1 and Python from 0; an incorrect assumption would
misalign every trial by one 20 ms bin. Tested across all 54 blocks by comparing
each block's maximum trial-stop index against its recorded `nPointsPerBlock`.
*Result:* 5 blocks have `max(stop) == nPointsPerBlock`; **0** have
`nPointsPerBlock − 1`; none overrun; the smallest start index anywhere is 88,
never 0. **Indexing is 1-based (MATLAB convention), confirmed.**

**Procedure 12. Construct a tidy data representation.**
Wrote `scripts/03_load_dataset.py`, translating the authors' MATLAB loader into
Python. It walks `participant/day_<N>/block_<M>/`, reads all three `.mat` files,
and produces a trial-level table, a block-level table, and per-block neural
matrices. Deliberate constraints: **no preprocessing is applied** (no z-scoring,
smoothing, detrending, or alignment), and **excluded trials are flagged, not
dropped**, so every such decision remains explicit and reversible.

**Procedure 13. Build automated data-integrity checks.**
The loader collects and reports inconsistencies rather than failing silently.
Implemented checks: behavioural-metric length disagreeing with trial count; trial
boundaries exceeding the neural matrix; missing neural matrix; feature count
varying between blocks; and indexing-convention mismatch.

**Procedure 14. Validate the pipeline against data with known properties.**
Generated synthetic `.mat` files replicating the expected structure, including a
deliberately corrupted variant containing each targeted defect. Verified that all
five integrity checks fired on corrupted input and that none fired on correct
input. *Rationale:* an integrity check that never triggers provides no assurance.

## Phase 1D — Exploratory characterization

**Procedure 15. Compute descriptive statistics and distributions.**
Ran `scripts/04_explore_dataset.py`, computing counts per participant, session,
block and trial; recording duration; feature counts; per-column data types,
missingness and uniqueness; distributions of all performance measures; and
excluded-trial proportions. Output: `reports/DATASET_EXPLORATION.md`.

**Procedure 16. Quantify session spacing.**
Computed inter-session intervals per participant to test the even-spacing
assumption underlying standard time-series methods.
*Result:* spacing is **uneven** — T11 gaps 3–24 days (median 8.5); T5 gaps 2–14
days (median 5). Within blocks, bins are evenly spaced at 20 ms.

**Procedure 17. Characterize performance over time.**
Computed median per-trial angle error per session (with interquartile range) and
block-level success rate (`percentCorrect`) for each participant, plotted as small
multiples with participant-specific axes.

**Procedure 18. Test for a task-type confound.**
Tabulated task name against session for each participant, to determine whether
changes in performance could be attributed to changes in task difficulty.
*Result:* **no confound** — each participant performed a single task throughout
(T11 `circleOfCircles`; T5 `Fitts`).

**Procedure 19. Cross-validate performance measures.**
Compared the trial-level measure (angle error) against the independently recorded
block-level measure (`percentCorrect`). The two agree in timing and direction,
supporting the reliability of both.

## Phase 1E — Verification of the study's premise

**Procedure 20. Test the fixed-decoder claim against the data.**
The project's premise requires that no decoder recalibration occurred. Because
`cursorVel` is the decoder's output and `nctx`/`spikePower` are its inputs, a
fixed decoder implies a constant input–output mapping. Fitted a linear map from
z-scored neural features to `cursorVel` independently in each of the 50
main-cohort blocks, then computed cosine similarity of each session's fitted
weight vector to that of the first session (`scripts/05_check_decoder_stability.py`).
*Prediction:* a recalibration produces a discontinuous jump toward similarity 1.0;
a fixed decoder under neural drift produces a smooth decline.
*Result:* smooth decline in both participants; largest single-session increase
+0.089 (T11) and +0.023 (T5). No recalibration signature.
*Stated limitation:* diagnostic, not proof — T11's decoder is an LSTM with
internal memory, which a memoryless linear fit only approximates.

**Procedure 21. Verify the premise against the primary publication.**
Retrieved the full text of Pun et al. (2024), *Communications Biology*
(PMC11494208) and extracted the Methods statements on decoder handling.
*Result:* decoder weights confirmed fixed for both participants. T11's LSTM was
trained on trial days 576–646, before the deposited data begin at day 658. T5's
decoder was "fixed for later closed-loop blocks and future sessions."
*Additional finding:* adaptive feature normalization was applied online
throughout — per-channel z-scoring on a 3-minute rolling window (T11) and a bias
correction with adaptation rate 0.3 that updates the decoder intercept (T5). The
system is therefore **not fully static**, and the authors state that mean firing
rate shifts were consequently already compensated.

**Procedure 22. Confirm independent agreement with published results.**
Compared quantities computed in this repository (before the publication was read)
against those reported by the authors: session counts and spans, early/late
performance split points, the timing of both recovery events, feature counts and
bin width. All agreed.

autocorrelation, Kendall's τ) were computed. No preprocessing decisions were
made. No operational definition of "deterioration" was adopted. These are
deferred until the definitions in `reports/DATASET_EXPLORATION.md` §6 are settled
and the synthetic control pipeline (Phase 2) has been validated.

## Phase 2 — Detector validation and study design

*Added 25 August 2026. Continues the numbering above.*

**Procedure 23. Build a positive and negative control pair on simulated data.**
Implemented three systems whose nature is known by construction
(`scripts/06_ews_controls.py`): a saddle-node bifurcation where critical slowing
down is present; monotonic decline plus noise with a constant recovery rate; and
rising noise with a constant recovery rate. The detector de-trends with a
Gaussian filter, computes rolling variance and lag-1 autocorrelation, summarises
each trend with Kendall's tau, and tests that tau **two-sided** against
AR(1)-matched surrogates. Two-sided deliberately: a compressed basin of
attraction can produce falling indicators before a transition, so a one-sided
test would miss real signals.

**Procedure 24. Establish that a single run is not a validation.**
Repeated Procedure 23 across ten random seeds. It passed 4 of 10, with every
failure a *miss* on the positive control and no false alarms on the negative
controls — establishing that the detector was underpowered rather than
over-eager, which a single run could not have revealed.

**Procedure 25. Diagnose the cause of low power.**
Quantified the simulated system's correlation time near the transition (~357
steps) and showed that de-trending at a shorter scale removes the fluctuations
carrying the signal. Power at sigma = 100 was 0.17.

**Procedure 26. Measure power and false-positive rate across analysis choices.**
Swept rolling-window length against de-trending strength
(`scripts/07_ews_power_sweep.py`), reporting the full surface rather than
selecting a setting silently. Also established the resolution limit: with N
repetitions the smallest measurable rate is 1/N, so a false-positive rate
"exceeding 0.05" with 12 seeds is an artifact rather than a finding.

**Procedure 27. Distinguish a faulty detector from a data-length limit.**
Held the detector fixed and lengthened the simulated record. Power rose 0.25 →
0.42 → 0.83 → 1.00 across 4,000 → 40,000 steps, establishing that the detector
is sound and that low power reflects record length. This is an empirical
restatement of van der Bolt et al. (2021) on this project's own pipeline.

**Procedure 28. Estimate correlation times of candidate observables in the real
data.** `scripts/08_record_length_check.py`. Found that raw binned neural
features are near-white at 20 ms (0.3–0.5 bins of memory) while cursor velocity
has 27–52 bins, establishing that critical slowing down cannot be measured on raw
features at that resolution.

**Procedure 29. Reproduce the published baseline.**
Independently reimplemented Pun et al. (2024) Fig. 1b
(`scripts/09_reproduce_mindful.py`) and ran it on the downloaded data, obtaining
T11 r = 0.985 against a published 0.985, and T5 r = 0.980 against 0.983 —
confirming the pipeline end to end and providing the comparator the project must
benchmark against.

**Procedure 30. Compute the detectable effect size at each candidate analysis
level.** `scripts/10_design_power_analysis.py`. Derived exact Kendall tau null
distributions for n ≤ 8 and permutation nulls above, giving the smallest
detectable trend and the power curve for every sample size available in the
dataset, and identifying block level as the choice that moves the study from
marginal to usable.

**Procedure 31. Record the design decision and its alternatives.**
`research/design_decisions.md` documents four decisions, their interactions, four
coherent study designs and a recommendation, with all numbers reproducible from
Procedure 30. No design has been adopted.
